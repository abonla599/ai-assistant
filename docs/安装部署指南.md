# AI智能助手 - 桌面版打包部署指南

## 📋 前置要求

### 必需工具
1. **Python 3.11+**
   ```powershell
   python --version
   ```

2. **Flutter SDK** (已配置Windows桌面支持)
   ```powershell
   flutter doctor
   flutter devices  # 应显示 "Windows" 设备
   ```

3. **Visual Studio 2022** (或2019)
   - 安装时勾选"使用C++的桌面开发"工作负荷

4. **NSIS** (Nullsoft Scriptable Install System)
   - 下载地址: https://nsis.sourceforge.io/Download
   - 安装后确保 `makensis.exe` 在PATH中

5. **PyInstaller**
   ```powershell
   pip install pyinstaller
   ```

## 🛠️ 打包步骤

### 步骤1: 准备环境

```powershell
# 1. 激活Python虚拟环境（如果有）
.\venv\Scripts\Activate.ps1

# 2. 安装依赖
pip install -r requirements.txt

# 3. 确认Flutter Windows支持已启用
flutter config --enable-windows-desktop
```

### 步骤2: 编译Flutter Windows应用

```powershell
# 进入Flutter项目目录
cd flutter_app

# 获取依赖
flutter pub get

# 编译Windows版本
flutter build windows

# 验证输出
ls build\windows\x64\runner\Release\
```

编译完成后，可执行文件位于：
```
flutter_app\build\windows\x64\runner\Release\ai_assistant.exe
```

### 步骤3: 打包Python后端

```powershell
# 返回项目根目录
cd ..

# 使用PyInstaller打包后端
pyinstaller --onedir `
  --name "run_backend" `
  --hidden-import uvicorn.logging `
  --hidden-import uvicorn.loops `
  --hidden-import uvicorn.protocols `
  --hidden-import chromadb `
  run_backend.py
```

打包完成后，输出位于：
```
dist\run_backend\
├── run_backend.exe
├── _internal\          # 依赖库
└── ...其他文件
```

### 步骤4: 准备运行时文件

```powershell
# 返回项目根目录（若上一步进了 flutter_app 目录）
cd ..

# ⚠️ 不要把 .env / chroma_db / data 复制进 dist\run_backend\：
# PyInstaller 每次重建都会整体删掉那个目录，写在那里等于写在一个注定消失的地方
# （2026-09-16 真实丢过一次数据）。入口已从项目根读 .env、所有可变数据也钉在
# 项目根，见"🔐 多用户部署 → 运行时数据落在哪、怎么搬"。
# 这里只需要保证根上有 .env（密钥）与 data\ 目录（服务自己会建）。

# 1. 复制Flutter编译输出到dist根目录
cp flutter_app\build\windows\x64\runner\Release\* dist\

# 2. 复制启动脚本
cp start_ai.bat dist\
```

最终 `dist` 目录结构：
```
dist\
├── ai_assistant.exe          # Flutter前端
├── start_ai.bat              # 启动脚本
├── run_backend\              # Python后端文件夹（重建时会被整体删掉，不放数据）
│   ├── run_backend.exe
│   └── _internal\
└── ...其他Flutter文件

数据在项目根，不在这里：
<项目根>\.env
<项目根>\data\
<项目根>\chroma_db\
```

### 步骤5: 测试打包结果

```powershell
# 进入dist目录
cd dist

# 手动测试后端
.\run_backend\run_backend.exe
# （应看到 Uvicorn running on http://127.0.0.1:8000）

# 另开一个终端，测试前端
.\ai_assistant.exe
# （应能看到应用窗口并能与后端通信）

# 测试启动脚本
.\start_ai.bat
# （应先后启动后端和前端）
```

### 步骤6: 制作安装包

```powershell
# 返回项目根目录
cd ..

# 使用NSIS编译安装包
makensis installer.nsi
```

生成的安装包位于：
```
AI智能助手_Setup.exe
```

## 🔐 多用户部署：凭据、鉴权模式、数据落点与排障

这一节是**把服务交给别人用之前**必须读完的部分。代码里的规则都在
`backend/app/core/authz.py`（模式与中间件）、`auth.py`（身份库）、
`auth_router.py`（注册与管理端点），这里只讲运维要做的事。

### ACCESS_TOKEN 现在是什么

| | 旧含义 | 现在的含义 |
| --- | --- | --- |
| 它是什么 | 全站共用的那把访问口令，谁拿到谁就是"唯一用户" | **bootstrap 管理员凭据**（引导口令） |
| 解析成谁 | 所有人 | `default_user` / 用户名"本机管理员" / 角色 `admin` |
| 用途 | 每个请求都带它 | 1) 让本机 EXE 与**已经发出去的 APK** 不改配置继续可用；2) 冷启动时发出**第一批邀请码** |

- 给新用户的不该是这把口令，而是**用邀请码换来的个人令牌**（每人一枚、可单独撤销）。
- 配置位置：项目根的 `.env` 里 `ACCESS_TOKEN=...`（**不是** `dist\run_backend\.env`，
  那个目录每次重建都会被删掉，见下面"数据落点"）。
- 换掉它 = 换 bootstrap 口令：老口令当场失效，所有靠它直连的客户端要一起改。
- **不要把它写进任何分发物**（APK、前端静态文件、日志、公开仓库）。本仓已经因
  `.env` 被跟踪导致 API Key 公开五个月付出过代价，这把口令是公开仓库情况下
  唯一真正的门。
- 管理员**不来自任何请求体**：只有两处能产生 admin——这把口令，以及运维手工把
  `data/users.json` 里某人的 `role` 改成 `"admin"`（逃生口）。API 没有写 role 的口子。

### AUTH_MODE 的两种取值

| 取值 | 行为 | 用在哪 |
| --- | --- | --- |
| 不配 / `enforced` / 任何未知取值 | 每条 `/v1/`（以及 `/docs`、`/redoc`、`/openapi.json`）都要凭据，匿名 401；文档路由**在启动时就不生成** | 任何可能被外人访问到的部署（**默认**） |
| `disabled` | 所有请求一律以**本机管理员**身份运行，启动时打印一行警告；文档路由照常开 | 只用于本机开发 |

判定只看字符串是否等于 `disabled`，写错（`dissabled`、`false`、空串）都落到
`enforced` 那一侧——**未知取值按安全侧处理**，这条有测试钉着。

### 没有凭据 = 503，不是"门开着"

`AUTH_MODE` 不是 disabled、`ACCESS_TOKEN` 为空、且 `data/users.json` 里没有任何
`role=admin` 的人 —— 此时服务端**一个可服务的身份都没有**，所有受保护端点直接返回
`503 {"detail":"服务端未配置访问凭据"}`。**这是刻意的 fail-closed**：忘配 env 绝不等
于把一台 API 公网敞开。唯一的免凭据端点仍然是 `POST /v1/auth/register`（否则第一个
身份永远注册不出来）。

排障对照：

| 现象 | 意思 | 该做什么 |
| --- | --- | --- |
| `503 服务端未配置访问凭据` | 没配口令、库里也没有 admin | 在 `.env` 配 `ACCESS_TOKEN` 并重启；或手工往 `data/users.json` 写一个 admin |
| `401 缺少或错误的访问凭据` | 有身份可服务，但**这个请求**没带或带错了令牌 | 让用户在「设置 → 连接」重新注册，或管理员轮换令牌 |
| `403 需要管理员权限` | 身份是真的，角色不够 | 普通用户本来就不该看到这些端点，别放开；要改配置请用管理员口令 |
| `429 尝试次数过多` | 注册限流命中（见下一小节，隧道后是**全网共桶**） | 等 10 分钟；确认不是有人在猜码 |
| 前端显示"没有可用的模型服务" | 项目根的 `.env` 没被读到 | 检查 `.env` 在不在**项目根**（不是 dist 里） |

### 注册限流的桶：cloudflared 后面全网共用一格

`POST /v1/auth/register` 的失败计数键在 **`request.client.host`**，也就是 uvicorn 看到
的**对端地址**（不是 `X-Forwarded-For`）。窗口 10 分钟、阈值 10 次。走 cloudflared
隧道时后端看到的对端**恒为 `127.0.0.1`**，于是：

- 一次部署 = 一个桶。一个访客连着猜错 10 次，**所有人**在 10 分钟内都注册不了。
- 反过来，分布式猜码者也**不会**因为换 IP 而拿到新预算。所以这把锁在隧道部署上
  的实际作用是"防噪音 + 抬高单机脚本的代价"，不是"按访客限速"。
- 邀请码本身是 8 位去混淆字符集（≈40 bit，字母表 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`），
  个人令牌是 256 bit 随机串，猜中的概率不是这把锁的主要防线。
- 不计进桶的失败（都是正当用户的手滑）：用户名撞名（409）、用户名不合格（422）、
  **重复提交一枚已经花掉的码**。计费的是"这枚码压根不存在/不匹配"。
- 想让限流按真实访客分桶：让 uvicorn 看到真 IP——在可信的本地反代后面用
  `--proxy-headers --forwarded-allow-ips 127.0.0.1`（Cloudflare 场景由隧道写
  `X-Forwarded-For`）。**只对可信来源开启**，否则这个头本身就是伪造用的输入。

两个已知遗留（评审记录，本轮刻意不动，留给后续计划）：

1. **建议再加一条绝对上限**：与"猜码失败桶"无关、纯按端点算的注册速率上限
   （例如全局每分钟 N 次注册尝试）。今天没有，所以只要没人猜码，注册入口本身
   不限速。
2. **已花掉的码那一分支不计量**：重复提交一枚用过的码既不计数、对外措辞也与普通
   失败完全一致（仍是"邀请码无效"），所以它今天不构成枚举信道；遗留点在于这是一条
   **无预算**的请求路径，速率不受上面那把锁约束。

### 运行时数据落在哪、怎么搬

一切**可变数据**都挂在**项目根**（`backend/app/core/paths.py::data_root()` 单点提供）：

```
<项目根>\data\sessions.json      会话
<项目根>\data\users.json         身份库（令牌只存摘要）
<项目根>\data\invites.json       邀请码
<项目根>\data\providers.json     模型服务配置（含密钥）
<项目根>\data\uploads\           附件
<项目根>\data\feedback.json      反馈原文
<项目根>\data\preference.txt     偏好摘要（本机管理员那份）
<项目根>\data\preference-<uid>.txt  其余每个人的偏好摘要
<项目根>\chroma_db\              长期记忆向量库
```

- **绝不能落在 `dist\run_backend\`**：PyInstaller 重建会**整体删除**该目录
  （2026-09-16 真实丢过一次数据）。构建完必须复查 `dist\run_backend\` 只剩
  `_internal\` 与 `run_backend.exe`；重建前先 `ls dist\run_backend\` 确认里面没有
  `.env`、`data\`、`chroma_db\`。
- 每一份都可以用环境变量指走（放别的盘、测试隔离都靠它）：
  `SESSION_DB_PATH`、`USERS_DB_PATH`、`INVITES_DB_PATH`、`PROVIDERS_DB_PATH`、
  `UPLOAD_DIR`、`CHROMA_DB_PATH`、`FEEDBACK_FILE`、`PREFERENCE_FILE`。
  优先级：**环境变量 > `<项目根>\data\<文件>` > `<项目根>\<文件>`（历史兼容）**。
- 老版本把 `feedback.json` / `preference.txt` 直接写在**项目根**。服务仍会读那两份
  （不会丢历史），但要收进 `data\` 才与其它数据同源。搬法（**先停服务**）：

  ```bat
  move feedback.json data\feedback.json
  move preference.txt data\preference.txt
  ```

  搬完重启，日志里偏好摘要那行应显示 `data\preference...txt`。**别两边各留一份**：
  `data\` 下存在时以它为准，根目录那份从此不会再被写。
- 这些文件都在 `.gitignore` 里（且用的是 glob 形状，`preference*.txt` 一并兜住按人
  分账后的新文件名），**不要提交**。

### 签发第一个邀请码

管理员口令到手后的第一条命令：

```bat
tools\make-invite.bat
```

脚本从项目根 `.env` 读 `ACCESS_TOKEN`（避免手抄/进 shell 历史），向
`http://127.0.0.1:8000/v1/admin/invites` 发一次 `max_uses:1` 的签发请求，打印返回的
JSON。手工等价：

```bash
curl -s -X POST -H "Authorization: Bearer $ACCESS_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"max_uses": 1}' http://127.0.0.1:8000/v1/admin/invites
```

`max_uses` 可以给大于 1（一枚码给多人用），但**码明文只在发放响应与
`GET /v1/admin/invites` 里出现**，那是敏感串，别贴到群里——一对一发给本人。
邀请码今天**没有过期时间的设置接口**（`expires_at` 字段恒为 `null`），回收请用撤销。

### 管理员日常四条

```bash
curl -H "Authorization: Bearer $ACCESS_TOKEN" http://127.0.0.1:8000/v1/admin/users
curl -X POST -H "Authorization: Bearer $ACCESS_TOKEN" http://127.0.0.1:8000/v1/admin/users/<user_id>/disable
curl -X POST -H "Authorization: Bearer $ACCESS_TOKEN" http://127.0.0.1:8000/v1/admin/users/<user_id>/enable
curl -X POST -H "Authorization: Bearer $ACCESS_TOKEN" http://127.0.0.1:8000/v1/admin/users/<user_id>/rotate-token
```

- `disable` **当场**让那枚令牌失效；`enable` 是可逆的那一半，恢复后**原令牌继续可用**
  （轮换不会顺手解除停用，两件事各管各的）。
- `rotate-token` 返回新令牌，旧令牌立刻作废。
- `DELETE /v1/admin/users/<user_id>` 删人，不能删自己。
- 撤销邀请码：`DELETE /v1/admin/invites/<code>`（响应刻意不回显码明文）。

## ⚠️ 注意事项

### 常见问题

1. **Flutter编译失败**
   - 确认Visual Studio安装了C++桌面开发组件
   - 运行 `flutter doctor -v` 查看详细错误

2. **PyInstaller打包后缺少模块**
   - 使用 `--hidden-import` 添加缺失模块
   - 检查 `run_backend.spec` 文件中的hiddenimports列表

3. **NSIS编译失败**
   - 确认NSIS已正确安装且在PATH中
   - 检查 `installer.nsi` 中的文件路径是否正确

4. **安装包过大**
   - 清理不必要的依赖
   - 使用 `--exclude-module` 排除不需要的模块
   - 考虑使用UPX压缩（`--upx-dir`参数）

### 性能优化

- **启动速度**: 可通过减少Python导入模块数量优化
- **包体积**: 定期清理未使用的Python包
- **内存占用**: 监控后端服务的内存使用情况

## 🔒 安全建议

1. **不要提交 `.env` 文件到Git**
   ```bash
   echo ".env" >> .gitignore
   ```

2. **分发时使用 `.env.example`**
   - 让用户自行填写API密钥

3. **`ACCESS_TOKEN` 是 bootstrap 管理员口令**，不是"分享码"：别写进 APK、前端静态
   文件或任何公开产物里；给用户的一律是邀请码换出来的**可撤销个人令牌**。

4. **免凭据的公开面只有一个端点**（`/v1/auth/register`），名单在
   `authz.PUBLIC_PATHS`。往那里加第二条会当场让
   `backend/tests/test_route_auth_contract.py` 变红——那是刻意的，不是测试太严。

5. **代码签名** (可选)
   - 为EXE文件添加数字签名
   - 避免Windows SmartScreen警告
