# 项目规划书：把「AI 智能助手」做成一个有自己风格的 Agent 产品

本版日期 2026-09-21。路线由用户拍定：**A 打底 + C 做样 + B 放第三阶段**。
文中每条现状结论都在 2026-09-21 用只读核查对过代码，带 `文件:行号`；
**核查没覆盖到的写在 §7**，那几条不许被当成已验证事实引用。
这份文档是**方向**，不是日程——里面没有任何"几月几号交付"的承诺。

## 0. 先说三件会让这份规划书变卦的事实

写路线之前先把地基照片摆出来，因为其中两条和会话里传下来的说法不一致：

1. **`/v1/tasks` 不是洞，是"关着的门"。** 四条 tasks 端点全部 `require_admin`
   （`backend/app/main.py:793,806,834,853,871`），并且 `test_route_auth_contract.py:399-411`
   专门扫 `/v1/tasks*` 防降级。所以"把归属补上"的真实含义不是修漏洞，而是
   **把任务这一面从管理员独占放开给普通用户的前置工程**。
   它旁边有个更要紧的问题：`task_store` 是**进程级内存 dict**（`app/agents/task_store.py:41-43`），
   重启即丢——一个跑不了持久任务的后端谈不上 Agent 产品。
2. **现网今天只有两个工具能被模型调到：`calculator` 与 `help`。** `web_search` 依赖公网
   DuckDuckGo（本机出口探测不通）、`execute_code` 依赖 Docker（本机没有），两者被
   `registry.py:57-60` 的可用性裁剪**从清单里剔除**。而且 `agents/react_agent.py` 那条
   ReAct 循环基本触发不了工具：它调 `get_llm_response` 只拿回正文字符串
   （`llm_client.py:35` 丢掉 `tool_calls`），而 `_extract_tool_calls`（`react_agent.py:201-228`）
   只认 ```json {"tool":…}```，系统提示词从未要求那个格式。
   **结论：工具层是"重建"，不是"接着加"。**
3. **服务端今天存的密钥是明文。** `data/providers.json` 明文落盘、无任何加密
   （`providers.py:114-119`，全仓没有 cryptography/Fernet），provider 记录里**没有 owner 字段**
   （`providers.py:231-239` 的白名单里没有），`mask_key` 泄露前 3 位 + 后 4 位 + 总长度
   （`providers.py:38-43`）。好消息是这个文件没进 git（`.gitignore:7` 的 `data/`），
   坏消息是它和"用户自带 key"这条商业路线正面冲突——所以第一阶段的主线确实是它。

## 1. 这个产品到底是什么（一句话 + 三条不做）

> **一个跑在你自己服务器上的多租户 AI 助手：模型可以是你自己买的那家，
> 界面、记忆、动手的都是它自己的。**

用户已定的四条定位（2026-09-20 会话原话整理）：

| 维度 | 已定 |
| --- | --- |
| 给谁用 | 自己和朋友圈子的工具；**未来约两年内会对外运营**；能力一步一步来 |
| 钱 | **用户自带 API key**（不给用户垫钱） |
| 部署 | **先本机，上云是第二阶段** |
| 风格 | 人设、垂直场景与自己的工具、视觉与交互、记忆与自进化机制——**四类全要** |

明确**不做**的三条，写死免得每次会话重新吵：

- 不做桌面单机形态。（2026-09-19 已拒，理由：三周鉴权工程买的是"能发给朋友"，
  选桌面等于撤回这个能力；文件工具在多租户下是防火墙不是缺口。）
- 不给普通用户开读写本机文件的工具。（同上，管理员路径要开必须先有逐次审批层。）
- 不做 iOS。安卓先把 14 项验收走完，iOS 是"以后"。

## 2. 今天有什么、缺什么

按"能不能站住"分两列，左边是已经验证过的资产，右边是缺口。**缺口那一列就是这个产品的工期。**

| 领域 | 站得住的（可直接复用） | 站不住的（要重做或从零） |
| --- | --- | --- |
| 身份与隔离 | 密码登录 + 自助找回（三道固定题）、注册开放、记忆按 `user_id` 服务端强制覆盖（`memory_manager.py:204-208`）、路由级鉴权契约测试 | 没有任何"这把 key / 这个任务属于谁"的概念；管理员只能靠手改 `users.json` |
| 模型接入 | Provider 三层（内置目录/用户覆盖/每人选中）设计已定稿；实测可直连五家（DeepSeek/Kimi/智谱/硅基流动/通义）；默认模型前后端已收一 | key 明文落盘、无 owner；`_fail_reason` 把上游异常 `str(e)[:160]` 原样拼进 **stderr 与响应体**（`main.py:379,465,675`），未做故障注入验证 |
| 动手（工具） | 两条调用路径今天**都**带工具（`pipeline.py:118-160` / `streaming.py:44-105`），5 轮封顶 | 实际可用工具 2 个；无成本护栏、无重复调用检测、**无审批层**（全仓 grep `approv` 零命中）；任务存储不持久 |
| 上下文 | 附件文本截 20000 字符（`uploads.py:34`）；`assemble()` 已设计好 | **全仓无 token 计数**（grep `tiktoken`/`count_tokens` 零命中）；历史由**前端**截，按 `pref.contextWindow` 取最后 N 条（`app.js:170-173`，默认 10）；工具输出原样全量回灌（`pipeline.py:152-156`） |
| 记忆 | 每轮自动召回 top_k=3 + 自动写入；`relevance * weight` 排序（`ranking.py:21`） | 写入是"取前 100 字原文"（`pipeline.py:162-169`）——存的是话，不是事实；无自动衰减（刻意，见 `memory_weight_updater.py:34-37`） |
| 交付形态 | 安卓 WebView 壳（提醒/分享/组件/快捷方式/检查更新五件事）、CI 出包发 Release、官网 www.fenever.xyz、隧道+崩溃守护+可观测 | 壳的 14 项真机验收基本没走；能力都还只在"我们手上没有真机"的推断里 |
| 风格 | 深色/浅色主题、登录开场动画、弧形面板常驻结构 | **人设是一句硬编码提示词，不是可配置的产品件**；视觉没有自己的标识 |

一句总纲：**"能对话、能记住、能发给朋友"这三件事已经成立；"能自主动手、能算清账、能长成自己的样子"这三件事还没开始。**

## 3. 四类"风格"分别做成什么（这是"我自己的想法"那一半）

这四条不是装饰，每条都配一个可判据，否则它就会在实现时缩水成一句文案。

### 3.1 人设与对话风格
- 做什么：把系统提示词从代码里的字符串变成**一层可配置的资产**——底座人设（不可被用户改掉的
  安全与诚实约束）+ 风格档（`calm` / `coach` / `blunt` 三档起步）+ 用户自己那一句。
- 判据：同一条输入在三个风格档下输出肉眼可辨；换风格**不**改任何后端代码；`grep` 找不到
  写死的中文提示词字面量（进源码锁）。
- 为什么值得：**这是四类里唯一一种"不加任何功能也能让人感觉到产品换了"的改动**，
  而且它是后面垂直场景的语气载体。

### 3.2 垂直场景与自己的工具（第一阶段就做这个，见 §4 阶段一·C）
- 选哪个：**「今天该干什么」——考研备考执行官。** 选它的理由不是它最赚钱，是它同时压到三件事：
  - 验证**人设**：教练口吻、不许废话、误报一次就再也骗不到我。
  - 验证**工具**：它必须真的动手——读当天计划、算进度差、**把提醒写进手机**
    （壳里那套 AlarmManager 已上线，但后端今天**没有提醒工具**，这就是第一个真工具）。
  - 验证**记忆**：它要记得"我线代特征值一做就错""昨天一点才睡"，并据此**改变明天的排片**——
    这一条会直接暴露"记忆只存前 100 字"不够用。
  - 附带价值：写提醒是一个**有副作用的动作**，它会把"要不要审批层"这个问题从抽象变成具体。
- 判据：早上对它说一句人话 → 手机上真的出现一条对得上号的提醒 → 第二天它记得昨天没完成 →
  全程不写一行前端代码。

### 3.3 视觉与交互
- 做什么：一个标识（一个符号 + 一种排印节奏，不是"再来一套渐变"）、一套状态语言（空/加载/错误/
  边界/权限，四类里现在只做了前三类的雏形）、把这套语言**同时**落到 PWA 首屏、桌面组件、官网、
  APK 图标四处。
- 判据：把四处截图并排放，陌生人能认出是同一个产品；组件与 App 的间距/圆角/字重同源。
- 刻意不做：主题商店、自定义皮肤。多租户下这是无底洞。

### 3.4 记忆与自进化机制
- 现状是"存话"，要改成"存事实"：给记忆加 `kind`（偏好 / 事实 / 进度 / 约定）与 `scope`
  （全局 / 某场景），进度类只写结构化事实不写原文。
- 自进化的最小可信形状：`weight` 现在**只被显式动作改写**（反馈夹 0.1–5.0、管理员 decay），
  本产品要的是"**用过且没被否定**就微微涨、被纠正就明显降"——注意这条如果做错就是另一种谎
  （`memory_weight_updater.py` 当年就是每轮打一句谎）。所以：**先有账（谁在什么时候用了哪几条）
  再动权重**，这是 B 排在第三阶段的真实原因之一。
- 判据：同一条错误偏好，纠正一次之后**下一次不再被召回**；且能拿数据回答"这条记忆为什么被用"。

## 4. 三阶段路线

### 阶段一（A 打底 + C 做样，同一阶段并行）

**A 线：把 key 与账本做硬。** 顺序不能换，因为后一条依赖前一条的数据结构。

1. **落地已定稿的"自带模型 = 浏览器直连"**
   （`docs/superpowers/specs/2026-09-19-user-owned-models-direct-connect-design.md`，四条待拍已全拍定）。
   这是"key 安全"最彻底的做法：**服务端那张 `user_models` 表根本没有 key 这一列**，
   不是"不返回"而是"没有可泄露的东西"。需要动的结构：`ChatPipeline.process` 拆成
   `assemble()` + 调用；新增 `POST /v1/chat/prompt` 与 `POST /v1/chat/commit`；
   `used_memory_ids` 留在服务端一次性票据里，绝不让客户端回传。
   - **它有一道前置闸门，而且不在代码里**：那份 spec 的 §9 写着"实现前必须先验的一件事"——
     在**真机浏览器**上跑通一次 DeepSeek 直连（SSE 增量、中途断网、401/429 文案）。
     桌面能验协议与 CORS（2026-09-19 已验过两家预检都放行 `authorization,content-type`），
     但**移动 WebView 的混合内容与 CORS 行为差异只有实机能定论**。跑不通就不该动 `pipeline.py`。
     所以 A 线第一个动作是做一个探测页（键只在用户浏览器里、绝不打到我们服务器），
     发给有真机的人跑一遍，而不是先写后端。
   - **探测页已就位**：`/site/probe.html`（`backend/app/web/site/probe.html`）。六项：流式连通、
     `usage` 回传、非流式、错 key 的报错文案、中途 abort、以及必须人肉配合的"跑到一半开飞行模式"。
     它匿名可访问、对本站零请求、不落任何存储、报告里连 key 的长度都不出现——这几条各有一把锁
     （`test_website.py`，六次变异逐条验证过红在预期那把）。
     **它现在还没上线**：`/site` 下的文件是打进 EXE 的 datas，要等下一次重建 EXE 才可达。
2. **管理员那把 key 也照同一标准收敛**：`providers.json` 里的 key 从"记录的一个字段"变成
   **独立的密钥文件 + 记录里只留引用**；`mask_key` 改为**只给末 4 位、不给前 3 位、不给长度**
   （长度本身就泄信息）；给 `_fail_reason` 加一道"上游异常文本进日志/响应前过一遍密钥形态"的
   过滤，并用真实故障注入证伪"它不会把 key 吐出来"。
3. **账本（这是本阶段真正的产品件）**：
   - **归属**：`providers` 加 owner 语义（管理员内置 vs 用户自带，两路在一张目录里合并但权限不同）、
     `task_store` 加 owner 并**落盘**（内存 dict 换成 `data/tasks.json`，与 sessions 同一套写法）。
   - **用量**：每次模型调用记 `{谁, 用哪条 provider, paid_by, 输入/输出 token, 工具轮次, 耗时, 成败}`，
     按天汇总。**账分两半算，别混成一件事**：
     - **记账用供应商回传的 `usage`**（OpenAI 兼容的流式在最后一个 chunk 里给，
       需要请求带 `stream_options: {"include_usage": true}`）——**不引本地 tokenizer**，
       因为各家分词器不同，本地算出来的数拿来要钱是错的。**这一条用前必须实测一次**
       （DeepSeek 与 DashScope 是否都回、`include_usage` 是否被接受），没验过就别写进代码注释。
     - **预算用估算**：`assemble()` 里截历史与工具输出，只需要"别爆上下文"，不需要精确到 token。
       同一个函数里两套口径要在名字上就分开（`estimate_for_budget` / `record_from_usage`），
       否则三个月后一定有人拿估算值去对账。
   - **限流**：落地第五本账（键 `IP+user`，初值 60 秒 20 次）。规则沿用已有四本账的既有裁决：
     **任何成功都不还回预算**、计费挂标记不挂文案。
   - **待补的洞（顺手）**：`/v1/tasks` 补 owner 之后，才谈得上把它放开给普通用户；
     现在它连数据都不跨重启，放开只会做出一个"昨天设的任务今天没了"的功能。

**C 线：把「今天该干什么」跑穿。** 依赖 A 线的第 3 步（工具要能算进账），其余可与 A 并行。

- 新增**第一个真会动手的工具**：`set_reminder`，走壳的 JS 桥（`ShellBridge` 已有能力协商机制，
  `capabilities()` 现成可加一项），后端不假装自己会响铃。
- 新增**第一个只读工具**：`today_plan`——读的是用户**上传一次**、服务端结构化存下来的日程表，
  **不是**给模型开文件读（见 §1 的"不做"第二条）。
- 人设先只做一个风格档：`coach`（为这个场景服务），但**结构按三档预留**，避免变成硬编码。
- 记忆加 `kind` 字段，进度类走结构化事实；这一步不做权重，只把"账"要用的字段留出来。

**阶段一完成判据（六条，缺一不算完）**
1. 用浏览器直连自带 key 完成一轮对话，服务端 `data/` 全量 grep 不到这把 key 的任何形态。
2. 关掉服务器再开起来，昨天设的备考提醒任务还在，且属于正确的人。
3. 答得出"昨天到今天，每个人用了几次、消耗多少 token、谁的钱"——数据来自账本，不是日志 grep。
4. 早上说一句人话 → 手机真出提醒；纠正它一次排片错误 → 第二天不再犯（记忆判据）。
5. 上下文有硬上限，且超限的行为是**截断并告知**，不是静默丢或 502。
6. `pytest` 全绿，且上面每条都有对应的**负向测试**（沿用本仓规矩：每条锁都要变异验证过会变红）。

### 阶段二：上云 + 对外运营（把"朋友圈子"这条边界换掉）

- 形态不变（在线多租户），换的是**运行位置与隔离假设**：本机 EXE → 云主机/容器。
  现在整套运维（隧道、看门狗、PyInstaller 产物、`config.yml`）是围着"这台 Windows"写的，
  这一层要重写成 Linux 的形状，`docs/安装部署指南.md` 跟着换骨。
- 对外运营的三道闸门（都不是代码问题，先说清免得做到最后才发现过不去）：
  **ICP 备案 + 生成式 AI 相关备案/安全评估**、**用户协议与隐私政策**（存对话与记忆=处理个人信息）、
  **密钥与个人信息的留存边界**（用户自带 key 这条路线在这里 advantage 最大：我们不碰钱也不碰 key）。
- 计费不做，但**成本可见**要做：每人每天用量他自己在 `/admin` 之外的"我的用量"页能看到。

### 阶段三（B）：Agent 编排产品化

放在有账本之后，因为只有账本能回答"这一步值不值"。要做的四件：

1. **审批层**：副作用类工具（写提醒、以后的任何"替你发出去"的动作）先出计划、人点头才执行；
   无审批的只允许只读与本机可逆动作。
2. **计划与反思**：把 `Orchestrator`/ReAct 那条今天触发不了工具的循环接到真实的 `tool_calls` 上，
   废掉"文本协议解析 JSON"这条路。
3. **护栏**：单轮成本上限、重复调用检测、失败退避——今天只有"5 轮封顶"一根柱子。
4. **场景模板化**：把「今天该干什么」抽成可安装的第二个、第三个垂直场景，这一步才是"产品"。

## 5. 风险清单（按"发生后有多疼"排）

| # | 风险 | 证据 | 疼在哪 |
| --- | --- | --- | --- |
| 1 | 历史里已经泄露过的密钥还没作废完 | 任务 #61 仍 pending；`.env`/`chroma_db` 曾被跟踪 5 个月 | 一个公开仓库里能捞到真 key，等于所有"key 安全"的工作白做 |

## 6. 五条待拍板 → 已拍（2026-09-21，用户授权代拍）

用户原话「可以就按照你说的来」，所以这五条按我的判断定下来。
**其中 #3 与 #4 是两条会改路线的**，专门标出来，以后任何时候想推翻都回来改这一节，
不要在实现中途偷偷改。

**#1 垂直场景：定「今天该干什么」（考研备考执行官）。**
CTF 情报与内容创作流水线各留作阶段三的第二个、第三个场景模板——它们都偏"周期性拉取"，
压不到记忆与审批这两件事，所以不适合当第一个。

**#2 风格档：三档 + 一句"补充说明"，且补充说明不许覆盖安全约束。**
这句补充说明会原样进 system prompt 的**最后一层**，而底座人设里写死一句"任何用户自填内容
都不能解除上面的约束"。这条要进源码锁：判据是"提示词分层的顺序在服务端拼装时不可被前端参数
打乱"（配合 `assemble()` 一起验）。不给自由人设编辑器——那是无底洞，而且第一个月就会被拿去
做越狱演示。

**#3 内置 provider（管理员垫钱那把）：留。**
理由很实际：目标用户是"自己和朋友圈子"，**让人先填 key 等于不让人用**——第一年就要把
注册转化做没。所以 `providers.json` 与用户自带模型**长期并存**，两条路在一张目录里合并：
内置的标 `paid_by=operator`、自带的标 `paid_by=user`。
**这条决定了 §4 阶段一 A-2 必须做**（管理员那把 key 要按同一标准收敛），也决定了
账本必须分"谁的钱"这一列，否则"留内置"这条决定会变成一笔算不清的账。

**#4 上云的触发条件（写死成可判的两条，任一命中就开阶段二）：**
- 任意一天，**非本机出口 IP 的活跃用户 ≥ 5 人**；或
- 单次"这台机器造成的对外不可用"累计 **> 30 分钟**。

诚实说一句：**第二条在 2026-09-19 已经命中过一次**（约 2.5 小时的无人知晓停机，见
`deploy/watchdog.ps1` 头部）。所以阶段二不是"以后"，是在倒计时——这条要写在脸上，
免得我们把运维韧性一直花在一台单点上。

**#5 壳的 14 项真机验收：不单独追，改成"随下次发版压成 5 条发出去"。**
我们手上没有安卓真机，这 14 条只能靠用户的手。它的正确形状不是"记在文档里等谁有空走一遍"，
而是**下次出 APK 时把最关键的 5 条写进 Release 说明**（通知、分享收件、组件跨账号、
覆盖安装是否保令牌、检查更新能否出包），让装包的人顺手就答了。它不挡阶段一的代码，
但挡"我们把产品对外说成什么样"的可信度——所以这条一旦实现，官网与 Release 文案里
没验过的能力一句都不许写（这条规则已经在 `docs/` 与 workflow 里，别松）。

## 7. 本版没验到的部分（引用这份文档前先读这一节）

只读核查自己交回来的四条"没确认"，加上我判断需要点出来的：

1. **上游异常文本会不会带出 key——没做故障注入。** 构造一次真 4xx（比如故意写坏 base_url），
   看 `data/backend.log` 与响应体里有没有 Authorization 的任何片段。在验之前，§5 风险 #2 的
   严重度只能按"未知"算。
2. **`orchestrator.run` 那条链能不能拿到当前人**——加 owner 之前必须先确认写入侧拿得到
   principal，否则"补归属"会在中途变成"再拆一次调用链"。
3. **`/v1/tasks` 收紧为 `require_admin` 的提交历史没查 blame**，所以"它一直是关着的"
   这个判断只有代码与测试作证据，没有时间线。
4. **没启服务实测过发给模型的工具清单条数**（"今天只有 2 个"是静态判定 + 本机探测推出来的），
   也没查 `chroma_db` 里现存记忆的 owner 分布。
5. **安卓壳自己存不存密钥：已排掉，但排出来一个更大的问题。** `grep` 全壳源码，
   两块 SharedPreferences 只装 `reminders` 与 `shares_meta`（`PrefsIo.java:22,31`），
   **没有任何** `api_key` / `Authorization` / `Log.` 命中；且 `setWebContentsDebuggingEnabled`
   零命中，release 包的 WebView 挂不上 `chrome://inspect`。
   **但 `MainActivity.java:99` 开了 `setDomStorageEnabled(true)`** ——意味着形状 A 的
   "key 只在浏览器里"在手机上具体就等于"**key 在这个 App 的 localStorage 里，明文**"，
   而今天那块存储里已经躺着登录令牌（`app.js:96` 那段迁移读的就是 `localStorage.accessToken`）。
   这不是新洞，但它把"自带模型"逼出一个必须先答的问题：**手机端到底把 key 放哪儿**。
   见 §5 风险 #9 与 §4 A-1 的探测项。
6. 本文所有"完成判据"都还没有对应的失败测试。**判据不配反例，就会长成第二份谎**——
   这条规则在 §8 的维护要求里再钉一次。
