## 1. 目标与范围

让一个跑在个人电脑上的多人助手，在**没有邮件、没有短信、没有任何外部服务**的前提下，把
"我是谁、我怎么进去、我忘了口令怎么办"三件事闭合。

范围内：

1. 注册增加**确认密码**与**密保问题（必填）**
2. 新增免凭据的**自助重置口令**端点与登录页的重置流程
3. 用户名重名的提示要显眼（红字 + 红框 + 焦点）
4. 首屏说明卡整块删除，登录层收成居中单列

范围外：设备指纹、邮箱体系、配额与计费、后端托管迁移。

## 2. 现状（已核实的代码行为，非推测）

| 事实 | 位置 |
|---|---|
| 口令登录：`pw_hash = "bcrypt:" + bcrypt(sha256(pw))`，先 sha256 是为绕开 bcrypt 72 字节截断 | `core/auth.py` `hash_password` |
| 一个用户可有多枚会话令牌（`tokens` 列表，上限 8，FIFO 挤出），换手机不必重新注册 | `core/auth.py` `MAX_SESSION_TOKENS` |
| `rotate_token` 清空全部令牌，且**不会**顺手解除停用 | `core/auth.py` |
| 登录失败三种原因（查无此人 / 口令错 / 已停用）对外**逐字节同一句话**，并用 `_DUMMY_PW_HASH` 均衡耗时 | `core/auth.py` `_LOGIN_FAIL` |
| 注册开放但按真实 IP 限流：失败 10 次/10 分钟、成功 3 次/24 小时；IP 取 `CF-Connecting-IP`（源站只听回环，隧道是唯一入口），`X-Forwarded-For` 明确不信 | `core/auth_router.py` |
| 重名已经是 409 +「该用户名已被占用」，但界面只把它当一行小字提示 | `core/auth.py:253`、`static/app.js` `submitAuth` |
| 管理员页有停用/启用/轮换令牌/删除，**没有任何改口令的入口** | `web/admin/admin.js`、`core/auth_router.py` |
| 免凭据路径只有 `/v1/auth/register`、`/v1/auth/login` 两条，由路由契约测试钉住 | `core/authz.py` `PUBLIC_PATHS` |

## 3. 已确认的设计决定（这一轮人拍板的四条 + 我补的两条）

| # | 决定 | 取值 | 理由 / 代价 |
|---|---|---|---|
| 1 | 密保何时设置 | **注册时必填**（问题 + 答案各一格） | 可选就等于没人填，自助重置这条路白修。代价：注册从 2 格变 4 格 |
| 2 | 重置后是否换密保 | **可选**，换不换由用户决定 | 人拍板。代价：答案若已泄露过一次，攻击者下次仍可重置 |
| 3 | 重置后是否吊销既有令牌 | **吊销全部**（等价于管理员那次 `rotate-token` 的清空效果） | 会走"忘记密码"的人，多半正是怀疑自己的账号被别人用着；留着旧会话等于把门开着。代价：本人其他设备要重新登录一次 |
| 4 | 库里现存的老账户 | 直接删，不迁移、不回填 | 人确认全是试验账户 |
| 5 | 重置成功要不要计入预算 | **计**：每 IP 每 24 小时最多 3 次成功重置（独立账本 `_RESETS`，不与登录失败预算混用） | 猜密保答案比猜口令容易得多；只罚失败不罚成功，等于允许"慢慢试到成功为止" |
| 6 | 后端要不要校验"两次密码一致" | **不要**，确认密码是前端的事 | 后端收一份 confirm 字段不增加任何安全属性，只多一个能填错的入口 |

## 4. 数据结构与端点契约

### 4.1 `data/users.json` 新增两键

```json
"u_4f9a21c7": {
  "user_id": "u_4f9a21c7", "username": "张三", "username_lc": "张三",
  "pw_hash": "bcrypt:$2b$...", "tokens": ["sha256:..."],
  "sq_q": "我小学的班主任姓什么",
  "sq_hash": "bcrypt:$2b$...",
  "role": "user", "disabled": false, "created_at": "...", "last_used_at": "..."
}
```

- `sq_q` 明文存：重置表单要把问题显示出来，它不是秘密。
- `sq_hash` 与口令同构：`"bcrypt:" + bcrypt(sha256(answer.strip().casefold()))`。**明文答案绝不落盘、不进日志**——它和口令是同一类东西。
- 归一化只做 `strip().casefold()`，不做别的（不剥标点、不小写化中文），否则"用户以为一样"的匹配失败比严格匹配更难解释。

### 4.2 `POST /v1/auth/register`（免凭据，入参扩到 4 个字段）

`{username, password, security_question, security_answer}`

- 密保问题/答案各自最短 2 字符、最长 100 字符，与用户名同样过滤控制字符；不合格 → 422 并**照实说是哪一格**（把"密保答案太短"推给"用户名不合法"会让人改错地方）
- 422/409 一律不烧限流预算（沿用现有"打字错误不是攻击"的判据）；只有密保答案错、口令错这类"猜"才计费
- 成功仍返回 `{token, user_id, username, role}`，注册即登录

### 4.3 `POST /v1/auth/reset-password`（新增，免凭据）

`{username, answer, new_password, new_question?: str, new_answer?: str}`

- `new_question` 与 `new_answer` 必须**同时给或同时不给**，只给一半 → 422
- 成功 → 200 `{"status": "reset"}`，**不发令牌**：让他回登录页用新口令进去。少一条"重置即拿到会话"的凭据发放路径
- 成功同时**清空该用户 `tokens`**（决定 3）：这次重置之前发出去的每一枚令牌，之后一律解不出来。
  与 `rotate_token` 的区别只在于不清新口令之外的东西——停用状态必须原样保留，别把"重置口令"变成第二次"顺手解除停用"
- 失败对外只有一句话，三种内部原因（查无此人 / 从未设密保 / 答案错）必须**同一句、同一形状、同一耗时**：
  `无法重置：请核对用户名与密保答案；仍未成功请联系管理员`
  否则这个免凭据端点就成了"哪些账号设过密保"的探测器。均衡手法沿用登录那套 `_DUMMY_SQ_HASH`
- 口令强度沿用注册那套规则（≥8 位），新口令与"该用户旧口令"相同也接受——不做历史比对，那需要多存一份数据换不来什么
- 计费：答案错 / 查无此人 → `_FAILS`（与登录、注册失败同一份 per-IP 预算）；成功 → `_RESETS`
- 必须同步进 `core/authz.py` 的 `PUBLIC_PATHS`，而 `test_route_auth_contract.py` 会立刻因为白名单对不上而红——那是刻意的

### 4.4 管理员侧不动

`/v1/admin/users/*` 保持现有的停用/启用/轮换令牌/删除。**不加**"管理员替别人设口令"的端点：
本轮已有自助重置这条路，多一个能改别人凭据的口子就多一处必须审计的写路径。

## 5. 登录层（最终形态）

下面这张图是**注册模式**的样子（格子最多的一种）；重置模式复用同一层，只把中间换成
"密保答案 + 新密码 + 确认新密码"三格，登录模式则只剩最上面两格。

```
        [图标] AI 助手
   用户名自己定，密码至少 8 位。……        ← 副标题，随模式变
  ┌ 请输入用户名 ─────────────────
  ┌ 请输入密码            (眼睛) ┐        ← 胶囊框，focus 变蓝
  ┌ 请再输入一遍密码 ────────────┐        ← 仅注册/重置模式出现
  ┌ 密保问题（自己看得懂就行） ───        ← 仅注册模式
  ┌ 密保答案（忘了口令靠它） ─────┐        ← 仅注册模式
  忘记密码                立即注册         ← 两个文字链接
  ┌──────── 注册并登录 ────────┐          ← 大胶囊，提交挂 form.submit
  提示行（错误红字 / 进度灰字）
```

- **说明卡整块删除**：`.auth-side`、`.auth-host`、`#authHost`、`showAuth()` 里填域名那句、
  以及钉它们的 CSS 断言一起走。两列随之变成单列居中（`max-width: 420px`），窄屏不再有塌陷分支。
- 三种模式共用同一层：`login` / `register` / `reset`。「忘记密码」不再只写一句提示，而是把
  这层切到 reset 模式（用户名 + 密保答案 + 新密码 + 确认新密码），提交打 §4.3 那个端点，
  成功后自动切回登录模式并提示「密码已重置，用新密码登录；其他设备需要重新登录一次」——
  后半句是决定 3 的直接后果，藏起来只会让人以为别的设备坏了。
- 重名：409 时提示行红字写**「该用户名已存在」**，同时给用户名那一格加红边并把焦点落上去。
  后端文案（"该用户名已被占用"）不动——它是存储层的实话，且已有测试钉着；换说法是界面的事。
- 确认密码两次不一致：**不发请求**，直接提示"两次密码不一样"。省一次 422 往返，也不白烧预算。
- 眼睛按钮只翻首屏这一格的 `type`，不清空已输入的值。

## 6. 安全权衡：为什么密保这条路比口令弱，以及我们认了什么

必须写在明面上，否则它会以"有找回密码功能"的面貌被当成一件安全增强。

1. **密保答案是可猜、可社工的凭据**，熵通常远低于 8 位以上口令（"我最喜欢的水果"这类问题尤甚）。
   我们因此得到的是：任何拿到"用户名 + 一句关于他的常识"的人都可以改他的口令。
   唯一能压住它的是 §4.3 的预算（失败 10 次/10 分钟、成功 3 次/24 小时，按真实 IP）。
2. **重置吊销全部令牌**（决定 3）反过来带来两点：本人其他设备会被踢下线，需要重新登录一次；
   而"能猜中密保答案的人"因此获得一次可用的骚扰能力——他能让对方所有设备掉线（但他也能顺手改口令，
   所以这没有新开攻击面，只是把已有的破坏变得可见）。真正的撤销手段仍然是管理员的
   `rotate-token` / 停用 —— 这条得在 `/admin` 页面上看得出来。
3. **校园网 NAT 后共享一个出口 IP**：同宿舍几个人一起注册可能撞 3 次/24 小时的成功预算。
   这是既有取舍（09-17 已记进安装文档），本轮把同一形状复制到重置预算上，风险随之翻倍。
4. 老账户没有 `sq_hash`，因此**永远走不通**自助重置——它们会被直接删掉（决定 4），
   所以这个分支只在测试里存在，不在真实库里存在。

结论：对"发给朋友用的小工具"这个定位，1–3 可接受；要对外扩大使用范围时，密保这条路应当整块撤下，
换回"管理员重置"这一条唯一能审计的路。

## 7. 迁移

- 老账户（`老李`、`实验1号`、`实验一号`）按决定 4 **直接删除**：用 `/admin` 页的删除按钮，
  不写脚本、不回填 `sq_hash`。删除后 `data/users.json` 允许是空表。
- 新注册用户天然带 `sq_q`/`sq_hash`；`AuthStore._load` 对缺键**不做任何回填**，
  读到的就是"没设密保"，由 §4.3 的合并文案统一挡掉。
- 无 `.bak`、无迁移日志：本轮没有任何一条数据搬运，写"迁移"反而制造假风险。

## 8. 测试矩阵

**存储层**（`tests/test_auth.py`）
密保答案只存 bcrypt 摘要、明文不进文件；`casefold` 归一化生效；重置成功换口令不换密保 / 同时换密保两种路径；
重置成功清空 `tokens` 且旧令牌立刻解不出来（决定 3）；**同时不得解除 `disabled`**——这个洞在
`rotate_token` 上踩过一次，重置口令同样不该顺手启用账号；缺 `sq_hash` 的用户重置被拒；新口令强度规则复用。

**端点层**（`tests/test_auth_endpoints.py`）
注册 4 个字段缺任一到 422 且**说清是哪一格**；密保太短不烧预算；
重置三种失败对外逐字节同一句话（含响应体全等，不只状态码）；
查无此人与答案错的耗时差被均衡（沿用现有 spy 手法）；
成功 3 次后第 4 次 429；答案错计入 `_FAILS`；`new_question` 与 `new_answer` 只给一半 → 422。

**契约层**（`tests/test_route_auth_contract.py`）
`PUBLIC_PATHS` 恰好是 register / login / reset-password 三条，多一条少一条都红。

**界面层**（`tests/test_web_pwa.py`）
说明卡的 id 与 CSS 规则必须**不存在**（反向断言，防止它被"顺手加回来"）；
确认密码不一致时 `submitAuth` 不得发出请求；reset 模式提交打的是 `/v1/auth/reset-password`；
409 渲染出"该用户名已存在"并给用户名格加红边；
模式切换只影响这三组格子的可见性，登录模式不参与提交确认密码/密保。

**实机**：源码隔离实例（临时数据目录、假上游、不碰真实密钥）跑一遍注册 → 登出 → 忘记密码 →
重置 → 新口令登录；宽屏与 724px 窄屏各截一张图。

- 若将来要扩大受众：撤下密保，改为管理员重置 + 一次性恢复码
- 09-16 那份文档记的两条非阻塞遗留仍未动：`session_store._load` 缺形状分支的 `else`；
  `.corrupt` 用固定名，二次损坏会吃掉上一份留证
