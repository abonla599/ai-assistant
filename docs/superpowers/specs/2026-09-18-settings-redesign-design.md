## 2. 已确认的决定

1. **去掉 tab，一屏到底的分组列表**（照参考图的语法），重内容走二级页。P2 从根上消失，不必再算"5 个 tab 在 390px 够不够"。
2. 手机上弹层改成**接近全屏**：`inset: 0` + 顶部安全区 + 底部留 8px，**只留一个滚动轴**；桌面保持居中弹窗。
3. 分组：**账户 / 模型 / 对话 / 记忆 / 关于**，底部独立一张红色「退出登录」卡。
4. **简约优先，界面不教用户怎么操作**：所有说明性文字删掉（清单见 §6）。
5. 一级列表共 **11 行 + 1 张身份卡**，无一句解释文字。

## 3. 一级列表与 DOM 映射

```
[身份卡]  头像 · 用户名 · 右侧角色标签
账户      切换账户        值=N 个已登录   › 二级页（本轮先占位，见 §8）
          改密码          ›              二级页（复用首层 recoverForm 的三步）
模型      当前模型        值=模型名  ⇅    就地改（原生 select，就是 #modelSel）
          模型服务        值=N 个可用 ›   二级页，仅管理员
对话      角色设定        值=已填写/空 ›  二级页（textarea + 保存 + 清除）
          上下文长度      值=N 条   ⇅    就地改（stepper / range）
          导出本次对话    ›              直接执行
记忆      长期记忆        值=N 条 ›      二级页（添加 / 搜索 / 列表 / 删除）
关于      外观            值=深色/浅色 ⇅ 就地改（themeBtn 的行为）
          服务地址        值=host（只读回显，不点开）
[退出登录]  红字，单独一张卡
```

值的两种后缀是**语义**，不是装饰：`⇅` = 就地改，`›` = 进二级页。二级页统一左上角返回箭头 + 居中标题，与参考图同构。

「版本」那一行实现时删了：本文档原先写它进一个只读二级页，但前端没有任何版本源可读（FastAPI 那个 `1.0.0` 与发版号 `v0.11` 无关），在 JS 里写死一个字符串就是等着腐烂的第二个事实来源。发版号以 GitHub Release 为准。

## 4. 视觉规范

全部沿用现有变量，不新增色值：分组标题 `--text-3` 12.5px；卡片 `--surface` + `--radius`(14px)；行 `min-height:54px`（拇指热区，见 [[feedback-mobile-ui-clutter-and-targets]]）；图标线性 SVG 19px `--text-2`，**不用 emoji**（同一份字体里会渲染成彩色或方块，齿轮那次已经踩过）；值 `--text-3` 14px；行分隔 `--line` 1px，卡片内最后一行不画线；「退出登录」文字与图标 `--danger`。

## 5. 数据流

`openSettings()` → 渲染一级列表（值全部来自已有的 `state` 与 `pref`，**不为渲染列表新增任何请求**）→ 行点击：就地改直接调既有 handler；`›` 进二级页（同一弹层内换 view，不新开弹层）。角色在 `applyRole()` 已知，管理员行是否出现由它决定，沿用"默认收起、确认是管理员才放行"的既有规则（`index.html:148-151` 那段注释里的理由仍然成立）。

- 「凭据与找回是怎么工作的」这一行：我上一版 mock 加的，按"不教用户操作"一并删。

## 7. 测试

**要改的现有锁**（`backend/tests/test_web_pwa.py`）：
- `test_the_settings_sheet_has_a_chat_pane_that_everyone_can_reach` —— 结构没了。它真正要钉的是"普通用户能换模型、能改上下文条数"，改成钉新行：`当前模型` 与 `上下文长度` 两行**不得**落在 `data-admin-only` 容器里。
- `test_the_sidebar_foot_is_one_row_that_opens_settings` —— 其中 `themeBtn` 必须在 `data-pane="about"` 的断言，改成"必须在关于组"。
- 首屏 ID 接线清单 —— 随 §3 的增删同步。

**要新增的锁**：
1. 设置区与空状态**不得再有静态说明文案**（反向断言钉的是写死在 `index.html` 里的那几句长文，**不是** `.pane-note` 这个 class——`#provTestResult`、`#registerHint` 这类状态槽还在用它，按 class 钉会误伤）。防"顺手加回一句解释"。
2. 温度不出现在任何界面文案里（钉 P5 不再复活）。
3. `data-admin-only` 只包住建「模型服务」与「服务地址」两个二级页，**不得**包住模型选择与上下文长度（P6 的反向）。
4. 行热区：`.set-row` 的 `min-height` ≥ 44px（手机上点不准的根因）。
5. 图标必须是内联 `<svg>`，设置区不得出现 emoji 字形。

## 8. 与「切换账户」的接口

「账户」组的两行是为 `2026-09-18-account-switching-design.md` 预留的位置：本轮先把**形状**做出来（「切换账户」行 + 值 + 一个只有「添加账户」的二级页），清单与切换逻辑在那一份里实现。两份 spec 的实现顺序：**本份先，切账户后**（用户已定）。

## 9. 风险与天花板

- 一屏到底意味着"改上下文条数"要滚一下才看见；接受——换来的是 6 个 tab 变 0 个、且不再有藏起来的页。
- 二级页是同一弹层内换 view，浏览器历史不动；手机返回键会直接关掉整个设置而不是退回一级列表。本轮按"可接受"处理，若要改需 `history.pushState`，属另一件事。
- 删掉温度滑杆会让"我调了温度没反应"这个反馈彻底消失。这是**故意的**：一个不生效的控件比没有控件更坏。
